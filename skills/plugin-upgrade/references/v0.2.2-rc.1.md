### DSH-0.2.2-R1-02 · npm tree relocation on upgrade: openai moves from top-level to nested inside the dsh package; interrupted installs on Windows lock the tree differently

- **Type**: fix
- **Applies to**: maintainers upgrading the host via npm on Windows (or any platform where the old tree can be partially locked)
- **Touchpoints**: host install path
- **Action level**: conditional
- **Symptoms**:
  - In alpha.3, `openai` was a top-level dependency (`node_modules/openai`); in rc.1 it nests inside the dsh package (`node_modules/@deepseek-ai/dsh/node_modules/openai`). A tree-health check that looks for top-level `openai/index.mjs` will report a false missing.
  - On Windows, `npm install -g` over a tree with running processes fails with EPERM on `rmdir` — the running dsh web process holds read locks on native modules (`koffi.node`) inside the package. npm's cleanup step cannot remove the old tree, and the install exits without updating.
  - After the running process is stopped, a fresh install works; but npm may not re-extract partially-cleaned trees (see [alpha.3 card A3-08](v0.2.2-alpha.3.md) for the full runbook).
- **Migration recipe**:
  1. Stop the dsh web process **before** upgrading (Ctrl+C the terminal or kill the node PID — refreshing the browser is not enough).
  2. If the install fails with EPERM: verify the tree still works (`dsh --version` + headless), then rename the package directory aside and reinstall fresh.
  3. Verify with `dsh --version`, a headless round-trip, and — for tree health — check that the nested `dsh/node_modules/openai/index.mjs` exists (not the old top-level path).
- **Verification**: `dsh --version` prints rc.1; headless round-trip succeeds; nested openai `index.mjs` present.
- **Source**: first-hand upgrade 2026-11-05 (Windows, npm global prefix on E:\npm-global); [dsh-v0.2.2-rc.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.1).
