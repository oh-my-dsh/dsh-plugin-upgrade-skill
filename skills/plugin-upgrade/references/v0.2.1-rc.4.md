### DSH-0.2.1-R3-01 · Synchronization release: every workspace package re-versioned to rc.4 with a byte-identical CLI bundle; ACP stdout diagnostics fix

- **Type**: fix
- **Applies to**: every plugin — the compatibility ledger can add `0.2.1-rc.4` with no code review; plugins pinning exact `@deepseek-ai/*` subpackage versions (rare) must widen or bump their pins
- **Touchpoints**: none for plugin code (no service, slot, event, or UI contract changes); #7 only for tools that parse ACP stdout
- **Action level**: informational
- **Symptoms**:
  - `@deepseek-ai/dsh@0.2.1-rc.4` publishes with all 83 internal `@deepseek-ai/dsh-*` dependencies moved from `0.2.1-rc.3` to `0.2.1-rc.4`.
  - The CLI bundle is byte-identical: `lib/` (bin.js, plugin loader, profile boot, and every `.d.ts`) hashes match rc.3 exactly; no files added or removed.
  - Spot-checked subpackages `dsh-plugin-manager`, `dsh-web-app`, and `dsh-web-frontend` (the GUI asset carrier) each diff to rc.3 **only** in `package.json` — the frontend hash bundle that canvas/webview plugins render inside is unchanged.
  - The only behavior changes in the tag comparison are outside those spot-checked packages: MCP resource-listing and ACP account-catalog diagnostics no longer leak into stdout in ACP mode (release notes: "修复 ACP 模式下诊断输出混入 stdout 的问题"), plus two view-tab tooltip UI fixes. An ACP client that tolerated or filtered stray diagnostic lines on stdout can drop that workaround.
- **Migration recipe**:
  1. Add `0.2.1-rc.4` to the plugin's `compatibility.json` dsh list and cut a declaration release — no code change, no re-review of touchpoints.
  2. If (unusually) a plugin declares a dependency on a specific `@deepseek-ai/dsh-*` subpackage version, either widen the range or move the pin to `0.2.1-rc.4`; the APIs behind those pins did not change.
- **Verification**: run the plugin's smoke surface (panel open, one game/tool round-trip) under rc.4 — output must be indistinguishable from rc.3; a diff here indicates an environment problem, not a host change.
- **Source**: [dsh-v0.2.1-rc.4 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.4) (published 2026-10-28) and the tag comparison above ([cc4446eec](https://github.com/deepseek-ai/deepseek-harness/commit/cc4446eec) `fix(mcp): keep resource-listing diagnostics off ACP stdout`, [41736cdec](https://github.com/deepseek-ai/deepseek-harness/commit/41736cdec) `fix(acp): keep account catalog diagnostics off stdout`); the published packages themselves: [`@deepseek-ai/dsh@0.2.1-rc.4` on npm](https://www.npmjs.com/package/@deepseek-ai/dsh/v/0.2.1-rc.4) and the sibling versions of [`dsh-plugin-manager`](https://www.npmjs.com/package/@deepseek-ai/dsh-plugin-manager/v/0.2.1-rc.4), [`dsh-web-app`](https://www.npmjs.com/package/@deepseek-ai/dsh-web-app/v/0.2.1-rc.4), and [`dsh-web-frontend`](https://www.npmjs.com/package/@deepseek-ai/dsh-web-frontend/v/0.2.1-rc.4); first-hand npm pack diff (2026-10-27): CLI `lib/` SHA-1 manifest identical to rc.3, subpackage diffs limited to `package.json`.
- **Field note** (first-hand, 2026-10-27): the six maintained plugins (dsh-paste-input 0.2.16, dsh-file-trace 0.3.37, dsh-input-history 0.1.29, dsh-ui-progress 0.11.11, dsh-ui-whale 0.3.33, dsh-minigames 0.8.1) shipped same-day declaration releases adding rc.4 to their ledgers on this evidence; a full session (games panel, canvas rendering, persistence) ran unchanged under rc.4 before the declarations were cut.
