### DSH-0.2.2-R3-01 · Experimental DeepSeek chat import plugin + Windows desktop update fix; zero plugin API changes — six-plugin fleet verified zero-adaptation on rc.3

- **Type**: behavior
- **Applies to**: every plugin (health-check edge; no API surface moved)
- **Touchpoints**: none new
- **Action level**: informational
- **Symptoms**:
  - A new experimental first-party plugin imports past DeepSeek App / web conversations into a workspace; purely additive, third-party plugins unaffected.
  - Windows desktop in-app updates no longer fail to reopen the app (desktop-only fix).
  - First-hand: the six maintained plugins (paste-input 0.2.21, file-trace 0.4.8, input-history 0.1.34, ui-progress 0.11.19, ui-whale 0.3.38, minigames 0.12.5) boot and run on rc.3 with zero adaptation — only compatibility-ledger rows were added. This is also the edge where the plugins' friendly display names (`locale/*.json` `meta.title`) go live end-to-end (`exports` must allow the `./locale/*` subpath or the host cannot read them — the fix shipped with these releases).
- **Migration recipe**:
  1. Append the rc.3 row to the compatibility ledger, rebuild, release.
  2. Post-install health check per the runbook: `dsh --version` + one headless round-trip.
- **Verification**: dump-config lists every plugin; one headless round-trip succeeds; plugin manager shows friendly titles.
- **Source**: [dsh-v0.2.2-rc.3 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.3); first-hand fleet upgrade 2026-11-14.
