### DSH-0.2.1-R1-01 · Plugin lifecycle dependency sync: enable/disable/uninstall/update now resolve the dependency graph (hot-reload applies where possible)

- **Type**: capability
- **Applies to**: plugins that carry runtime dependency mappings (peer plugins resolved at enable), profile maintainers who previously hand-repaired dependencies after toggling or updating a plugin
- **Touchpoints**: #0 (install/update/uninstall/enable/disable steps of the recipe), #5 (plugin replacement lifecycle)
- **Action level**: optional
- **Symptoms**:
  - Enable resolves the plugin's dependencies; disable/uninstall clears stale mappings; update or reinstall hot-applies the replaceable plugin under hot reload (the A3-03 behavior now covering the full lifecycle), and non-hot-reloadable changes still request a restart.
  - Before the RC, version replacement needed a restart and stale dependency mappings could linger after uninstall (the A1-era lifecycle fixes were partial).
- **Migration recipe**:
  1. Nothing mandatory; retire runbook steps that manually re-installed dependencies after an update.
  2. After updating a plugin with dependencies, verify the dependent rows still resolve (the sync is automatic; the check is belt-and-braces).
  3. Treat a restart prompt after an update as authoritative (same rule as A3-03).
- **Verification**: disable a dependency-bearing plugin and confirm its dependents degrade cleanly; re-enable and confirm they resolve without a reinstall.
- **Source**: [dsh-v0.2.1-rc.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.1) ("新增功能" — 插件启用/停用/卸载/更新后的依赖同步).
- **Field note** (first-hand, 2026-10-17): a six-plugin web fleet crossed to `0.2.1-rc.1` with zero adaptation — `--dump-config` loads every row with zero errors, read-only runtime probes stay green, and the host keeps `webStartup` (the A2-11 resolution pattern carries through the whole 0.2.1 line). Declaration-only re-releases: dsh-ui-whale `v0.3.31`, dsh-file-trace `v0.3.33`, dsh-paste-input `v0.2.14`, dsh-input-history `v0.1.27`, dsh-ui-progress `v0.11.9`, dsh-minigames `v0.3.32` (tags on all three mirrors; `compatibility.json` gains the `0.2.1-rc.1` entry each).

### DSH-0.2.1-R1-02 · New experimental plugin seats ship in the RC composition: session state records, Claude Code Mods compat layer, devtools, reasoning translation, Git worktrees

- **Type**: capability
- **Applies to**: plugin authors evaluating the new extension points: per-session state records (write/read a plugin's own session records), a Claude Code Mods compatibility layer (validation-stage subset mapping onto harness plugins), the experimental developer-tools bundle (raw session log, chat↔body bidirectional location, embedded Node debugging; English-only UI for now), machine translation of reasoning traces (Bing/Google/paid DeepSeek Flash), and Agent-driven Git Worktrees
- **Touchpoints**: #5 (new slot/service registration surfaces), #2 (session state records are a new event surface)
- **Action level**: informational
- **Symptoms**:
  - All five surfaces are opt-in experimental plugins/bundles in the RC composition; existing plugins are unaffected until they adopt them. The Mods layer is explicitly a compatibility probe, not a compatibility promise.
- **Migration recipe**: none; consult each surface's own docs before adopting. The A2-10 experimental surfaces (session state records, worktrees, reasoning translation, session search) that shipped as previews are now the RC seats.
- **Verification**: enable one experimental plugin from the Plugins page and confirm the fleet still boots clean.
- **Source**: [dsh-v0.2.1-rc.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-rc.1) ("新增功能").

### DSH-0.2.1-R1-03 · RC round-up: agent plugin-creation entry, optional-plugin minimal mode, prompt preroll retention, tool-preparation display

- **Type**: capability
- **Applies to**: plugin authors (the Plugins page's new agent plugin-creation flow with draft retention), minimal-mode profiles (optional plugins now supported there, incl. official Claude Code/Codex composition packs for headless/SDK/ACP), and users (unsent prompt preroll survives draft restore and workspace switches; tool calls show arrived command/file/content previews during preparation)

- **Migration recipe**: none.
- **Verification**: open the Plugins page and start the agent creation flow; a draft is retained without executing until the requirement is sent.
