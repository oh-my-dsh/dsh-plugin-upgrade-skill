### DSH-0.2.2-R5-01 · Web-search provider routing: DeepSeek models use server-side search at no per-search charge; others default to DeepSeek Search API — zero plugin-surface change, six-plugin fleet verified zero-adaptation on rc.5

- **Type**: behavior
- **Applies to**: every plugin (health-check edge; no API surface moved)
- **Touchpoints**: none new (web-search routing is core-side)
- **Action level**: informational
- **Symptoms**:
  - DeepSeek models now execute web searches server-side — no per-search charge appears for them.
  - Other models default to the DeepSeek Search API for the web tool.
  - Plugins observing tool results may see identical web-search results through a different provider path; behavior is unchanged from the plugin contract.
  - First-hand: the six maintained plugins (paste-input 0.2.23, file-trace 0.4.9, input-history 0.1.36, ui-progress 0.11.20, ui-whale 0.3.39, minigames 0.12.18) boot and run on rc.5 with zero adaptation — only compatibility-ledger rows were added.
- **Migration recipe**:
  1. Append the rc.5 row to the compatibility ledger, rebuild, release.
  2. Post-install health check per the runbook: `dsh --version` + one headless round-trip.
- **Verification**: `dsh --version` prints 0.2.2-rc.5; one headless round-trip succeeds; a web-search tool call returns results without per-search billing for DeepSeek models.
- **Source**: [dsh-v0.2.2-rc.5 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-rc.5); first-hand fleet upgrade 2026-11-18.
