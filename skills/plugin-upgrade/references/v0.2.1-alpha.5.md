### DSH-0.2.1-A5-01 · New client slot `conversation.input.model.label`: plugins can relabel models per provider in the composer's model selector

- **Type**: capability
- **Applies to**: Web client plugins that present model-channel information in the composer (for example provider-mapping or model-directory overlays); plugins that already sit on the neighboring `conversation.input.*` surfaces
- **Touchpoints**: #5 (client slot registration), #2 (any model-directory metadata the label derives from)
- **Action level**: optional
- **Symptoms**:
  - A new registration point exists: plugins can customize the label shown for a model in the input box's model selector, keyed by provider/model channel. Nothing existing changes — the slot is an additive sibling of the existing `conversation.input` faces (`conversation.input.for`, `conversation.input.dock`), not a rename.
- **Migration recipe**:
  1. If your plugin shows model-channel info elsewhere (tooltips, side panels), consider moving that presentation onto the new slot so the selector is the single source.
  2. Register with the documented slot contract; return a label per model identity and fall back to the default when you have no opinion (do not blank out labels you do not own).
  3. Plugins that do nothing keep the stock labels — no action required.
- **Verification**: register a test label for one model, open the composer's model selector, and confirm only that model's row changes; unregister and confirm the stock label returns after reload.
- **Source**: [dsh-v0.2.1-alpha.5 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.5) ("其他变更").
- **Field note** (first-hand, 2026-10-17): a six-plugin web fleet crossed to `0.2.1-alpha.5` with zero adaptation — two of the six already sit on neighboring `conversation.input` faces (`conversation.input.for` for prompt-history recall, `conversation.input.dock` for the session progress bar) and neither conflicts with the new sibling key; `--dump-config` loads every row with zero errors, read-only runtime probes stay green, and the host keeps `webStartup`. Declaration-only re-releases: dsh-ui-whale `v0.3.30`, dsh-file-trace `v0.3.32`, dsh-paste-input `v0.2.13`, dsh-input-history `v0.1.26`, dsh-ui-progress `v0.11.7`, dsh-minigames `v0.3.31` (tags on all three mirrors; `compatibility.json` gains the `0.2.1-alpha.5` entry each). Operational note: a mid-install interruption of the global package replacement can leave the launcher in a half-renamed state (old tree hidden under temp names, new tree empty) — repair by renaming the temp entries back before reinstalling, and run global installs from PowerShell so `--prefix` backslashes survive.

### DSH-0.2.1-A5-02 · Fix round-up: `/`-menu skill refresh after plugin toggles, terminal query/retry hygiene, PTC guidance parity, Page Up layout fix

- **Type**: fix
- **Applies to**: users of the Plugins page (skill-menu staleness in open sessions), multi-terminal workspaces, PTC Mode consumers, and Windows/Linux users with a collapsed right sidebar
- **Touchpoints**: none (product surface; no plugin adaptation)
- **Action level**: informational
- **Symptoms**:
  - All fixes, nothing breaks: the `/` menu in an already-open session now reflects plugin enable/disable immediately; creating/restoring several terminals issues fewer redundant queries and failed terminals stop retrying on every panel switch; PTC Mode guidance gaps are filled and model-identity wording is aligned across SDK, Web, and headless; Page Up inside a text input no longer shifts the whole layout left with the right sidebar collapsed.
- **Migration recipe**: none; retire any local workaround that force-refreshed the session after plugin toggles.
- **Verification**: disable a skill-bearing plugin on the Plugins page and confirm the `/` menu in an existing session updates without a reload.
- **Source**: [dsh-v0.2.1-alpha.5 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.1-alpha.5) ("问题修复").
