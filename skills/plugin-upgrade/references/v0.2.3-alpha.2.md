### DSH-0.2.3-A2-01 · 0.2.3-alpha.1 is DOA — skip it entirely

- **Type**: behavior
- **Applies to**: every plugin (cannot even boot the host)
- **Touchpoints**: none reachable — the host never starts; the only action is version selection
- **Action level**: required
- **Symptoms**:
  - `dsh@0.2.3-alpha.1` (dist-tag `alpha`, 2026-11-22 03:45 UTC) fails on **every** invocation, including `dsh --version`:
    `SyntaxError: The requested module '@deepseek-ai/cordis-plugin-loader' does not provide an export named 'EntryValidationError'`
  - `dsh-app-boot@0.2.3-alpha.1` named-imports 4 symbols that exist in **no published** loader version (npm latest 1.1.0): `EntryValidationError`, `formatIssues`, `relocate`, `validateOptions`. Peer range `~1.1.0` resolves to a loader without them → ESM instantiation failure before CLI parsing. 100% reproducible in any clean environment.
  - Root cause: upstream monorepo carries the new RC loader as a vendored `workspace:~` package; the alpha was built from that tree but the loader was never published to npm.
- **Migration recipe**:
  1. **Never target 0.2.3-alpha.1** — compatibility ledgers and installer ranges skip straight from 0.2.2-rc.x to 0.2.3-alpha.2.
  2. If already installed: `npm install -g @deepseek-ai/dsh@0.2.3-alpha.2` (or roll back to 0.2.2-rc.5).
- **Verification**: `dsh --version` prints the version and one headless round-trip succeeds.
- **Source**: [dsh npm dist-tags](https://www.npmjs.com/package/@deepseek-ai/dsh?activeTab=versions) · first-hand upgrade 2026-11-22 (full incident chain in the local report `incident-dsh-0.2.3-alpha.1-loader-export.md`); alpha.2 verified working the same day (Node v24.14.1, one EBADENGINE warning only).
