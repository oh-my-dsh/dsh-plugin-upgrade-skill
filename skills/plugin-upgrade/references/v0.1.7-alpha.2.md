### DSH-0.1.7-A2-01 · `spill-policy` config: `maxInlineBytes` becomes `maxInlineTokens`

- **Type**: breaking
- **Applies to**: profile/composition files and plugins carrying a custom `spill-policy` configuration
- **Touchpoints**: #6 (settings/config surfaces)
- **Action level**: required-if-hit
- **Symptoms**: a custom `spill-policy` keeps its old `maxInlineBytes` key after the upgrade: the key is no longer read, so the intended retention budget silently falls back to defaults (and MCP images can become unavailable after text truncation, per the release notes).
- **Migration recipe**: rename the key to `maxInlineTokens` and re-express the budget in tokens (there is no fixed bytes-to-tokens ratio — re-set the number for your content, do not just reuse the old byte value). The new retention keeps the head AND tail of tool-result text and images within one shared estimated-token budget, and omitted content gets a readable access path. A spill-policy without either key is unaffected.
- **Verification**: trigger a tool result long enough to spill; assert the retained head+tail lengths match the new token budget and that an MCP image referenced after truncation still renders.
- **Source**: [dsh-v0.1.7-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.2).

### DSH-0.1.7-A2-02 · Vendored dependency auto-updates pin to same-minor patch releases

- **Type**: behavior
- **Applies to**: plugin installs whose dependency resolution pulls vendored packages (Cordis and the vendored set) or Node Addon System
- **Touchpoints**: #7 (packaging/dependency resolution)
- **Action level**: informational
- **Symptoms**: installing or updating plugins no longer auto-introduces a NEW minor of Cordis/other vendored packages or Node Addon System: automatic updates are restricted to patch releases within the same minor. Installs that previously jumped minors silently now stay pinned.
- **Migration recipe**: no plugin action. Awareness for fleet maintainers: after upgrading hosts and re-installing plugins, expect vendored-dependency versions in lockfiles to stay within the same minor; a lockfile diff showing a minor jump indicates an explicit dependency somewhere, not the auto-update.
- **Verification**: run the plugin install once and diff the lockfile: vendored packages and node-addon-system must change only within patch range.
- **Source**: [dsh-v0.1.7-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.2).

### DSH-0.1.7-A2-03 · First plugin installation auto-selects the most responsive npm registry

- **Type**: capability
- **Applies to**: plugin installation UX (Plugin Manager installs)
- **Touchpoints**: #7 (packaging/installs)
- **Action level**: optional
- **Symptoms**: none (additive). Previously the first install with no configured registry could fail or hang on an unreachable default.
- **Migration recipe**: no plugin action. On first install with no source configured, the host now probes and prefers the most responsive accessible npm registry; manual selection and private-registry settings are preserved. Air-gapped or proxy environments that relied on the old default should verify which registry gets selected (or pre-configure one).
- **Verification**: perform a first install on a clean profile; assert it succeeds without manual registry selection and the chosen registry is recorded.
- **Source**: [dsh-v0.1.7-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.2).

### DSH-0.1.7-A2-04 · Web pages reconnect automatically after a server restart; client bundles are cached at host boot

- **Type**: behavior
- **Applies to**: fleet verification workflows after a host upgrade (all client plugins)
- **Touchpoints**: none (host transport and module serving behavior)
- **Action level**: informational
- **Symptoms**: (1) After a Web-server restart, an already-open page now reconnects and resumes displaying replies automatically — the old manual refresh is no longer required for connectivity. (2) Client plugin bundles are read and cached when the host boots: editing a served `lib/client.js` on disk NO LONGER takes effect on page refresh alone (0.1.6-era behavior); only a host restart serves the new bytes.
- **Migration recipe**: no plugin action. Two workflow consequences for anyone patching or hot-fixing client bundles in the install tree (first-hand 2026-09-23 evidence across the 0.1.7 window): a client-bundle edit requires a host RESTART before the page sees it — a refresh-only verification reports stale content and can mislead a diagnosis; and the auto-reconnect means an open page may keep working across a restart even while it is running pre-restart client bytes, so verify the served bundle content itself (fetch the combo URL and inspect), not just that the page responds.
- **Verification**: edit one byte of a served client bundle; refresh the page and assert the change is NOT served; restart the host, refresh, and assert it IS served. For the reconnect: restart the host and assert the open page resumes receiving replies without a manual refresh.
- **Source**: [dsh-v0.1.7-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.7-alpha.2); first-hand install-tree observation 2026-09-23 (combo route served pre-edit bytes after refresh, post-edit bytes only after host restart).
