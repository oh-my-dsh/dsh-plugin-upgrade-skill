### DSH-0.2.1-A1-01 · Runtime invariant plugins and package `./invariant` exports are removed

- **Type**: breaking
- **Applies to**: plugins that export an `./invariant` companion (the registry pattern where `src/invariant.ts` registers into an `invariants` service), custom profiles that insert runtime invariant plugin rows, and any consumer importing `@deepseek-ai/dsh-<pkg>/invariant`
- **Touchpoints**: none (diagnostic-surface removal — pre-flight §0 export inventory)
- **Action level**: required-if-hit
- **Symptoms**:
  - The runtime invariant plugins and every package's `./invariant` export are gone from the host tree. A plugin whose companion registers into `ctx.invariants` finds no such service on this host; the companion entry point is inert, and an `inject = ['invariants']` declaration on that entry would fail to resolve if it were loaded as a plugin.
  - The plugin's **main** entry is unaffected: companions are separate export paths that only a host-side invariant registry would load. Extensions or custom profiles that reference the removed diagnostic entry points must adjust.
- **Migration recipe**:
  1. Main-path plugins need no change; keep shipping (or drop) the `./invariant` export at your discretion — 0.2.1 hosts simply never load it.
  2. Custom profiles or tools that import `*/invariant` should drop those references; the covered paths moved into ordinary tests upstream.
- **Verification**: `dsh --version` boots with no `invariants` service; the plugin mounts and functions normally without it.
- **Source**: [f028f2566](https://github.com/deepseek-ai/deepseek-harness/commit/f028f2566) `refactor: remove runtime invariant plugins`, [963715344](https://github.com/deepseek-ai/deepseek-harness/commit/963715344) `test: cover paths previously exercised only by invariant companions`, [f1f0dc54f](https://github.com/deepseek-ai/deepseek-harness/commit/f1f0dc54f) `docs: drop remaining references to removed invariant checks`. Release notes: "破坏性变更：移除运行时 invariant 插件及各包的 `./invariant` 导出".
- **Field note** (first-hand, 2026-10-04): a seven-plugin fleet where six plugins export `./invariant` companions mounted and ran unchanged on 0.2.1-alpha.1 — zero adaptation, companions inert.

### DSH-0.2.1-A1-02 · Composer stats split into separate `activity` and `usage` dock entries; the old `stats` row is gone

- **Type**: breaking
- **Applies to**: plugins that replace or override the composer's former `stats` row (the input-area statistics strip)
- **Touchpoints**: #5 (UI — composer/input area seats)
- **Action level**: required-if-hit
- **Symptoms**: the single stats row is replaced by two independent extension entries, `activity` and `usage`. A plugin that registered itself as the whole `stats` row no longer matches any seat: its registration is orphaned and the two new rows render from the host.
- **Migration recipe**: register against the specific entry you replace (`activity` or `usage`) instead of the old `stats` id; a plugin that only *adds* content next to the stats area is unaffected.
- **Verification**: with your plugin enabled, the composer shows the split entries and your surface renders where expected.
- **Source**: [219008286](https://github.com/deepseek-ai/deepseek-harness/commit/219008286) `refactor(ui-chat): register composer stats pills as separate dock entries`. Release notes: "输入区统计扩展拆为 `activity` 和 `usage` 两个独立入口；覆盖旧 `stats` 整行的插件需要更新注册 ID".
- **Field note** (first-hand, 2026-10-04): a fleet progress-bar plugin occupying `conversation.input.dock` (a different seat) was unaffected.

### DSH-0.2.1-A1-03 · Subpath plugins: display text and icons must come from subpath exports; the root `package.json` is no longer read

- **Type**: breaking
- **Applies to**: subpath plugins (packages exposing browser halves through subpath exports rather than the main entry)
- **Touchpoints**: none (packaging/metadata special surface)
- **Action level**: required-if-hit
- **Symptoms**: the host no longer reads a separate root `package.json` for subpath plugin display metadata; `description`-style display text and icons must arrive through the corresponding subpath exports. A subpath plugin relying on root-manifest display fields loses its name/icon presentation (the plugin still loads).
- **Migration recipe**: export the display text and icon through the subpath surface the host already loads; bundle authors should re-check icon precedence (the manifest icon order was also corrected).
- **Verification**: the plugin list and bundle pages show the intended display name and icon.
- **Source**: [d9a40155c](https://github.com/deepseek-ai/deepseek-harness/commit/d9a40155c) `docs(upgrade): subpath plugins use <subpath>/icon instead of package.json`, [ecedbbc2e](https://github.com/deepseek-ai/deepseek-harness/commit/ecedbbc2e) `fix(plugins): reuse locale metadata and export bundle icons`, [d12257c95](https://github.com/deepseek-ai/deepseek-harness/commit/d12257c95) `fix(plugins): preserve manifest icon precedence`, [f30aec98b](https://github.com/deepseek-ai/deepseek-harness/commit/f30aec98b) `fix(plugins): reserve package display resources for bundles`. Release notes: "子路径插件不再读取独立的 `package.json`".

### DSH-0.2.1-A1-04 · Schedule/automation ships in the default Web composition; reminder tools are mode-scoped and denied to delegated children

- **Type**: behavior
- **Applies to**: plugins and user patches around the schedule rows that [DSH-0.2.0-RC1-03](v0.2.0-rc.1.md) moved into `@deepseek-ai/dsh-experimental-schedule-bundle`, and tools that surface reminders
- **Touchpoints**: none (packaging/composition special surface — profile patch row ids)
- **Action level**: informational
- **Symptoms**: the Schedule service and the automation task page are now part of the default Web composition (superseding the rc.1 optional-bundle card for this edge); selections of the retired experimental bundle are cleaned up automatically while existing tasks are preserved. Reminder tools are provided per mode — available in Standard, Creator, and PTC, absent in Minimal mode and denied to delegated children (subagents), with the caller restriction enforced in the tool layer.
- **Migration recipe**: drop any patch that re-inserts the experimental schedule bundle; do not rely on reminder tools inside subagent prompts.
- **Verification**: `dsh --profile web --dump-config` shows the schedule rows in the default composition; a subagent asking for a reminder tool receives the refusal.
- **Source**: [c6dd90597](https://github.com/deepseek-ai/deepseek-harness/commit/c6dd90597) `feat(web): ship the Schedule service and task page in the Web composition`, [699f1a8dc](https://github.com/deepseek-ai/deepseek-harness/commit/699f1a8dc) `feat(schedule): deny the reminder tools to delegated children`, [1b1b09e1f](https://github.com/deepseek-ai/deepseek-harness/commit/1b1b09e1f) `fix(schedule): enforce the caller restriction in the tool layer`. Release notes: "自动化任务改为 Web 内置能力……旧实验组合包选择会自动清理".

### DSH-0.2.1-A1-05 · Style injection is owner-tracked: toggling a plugin no longer strips other plugins' styles

- **Type**: fix
- **Applies to**: plugins that inject CSS into the Web client alongside other style-injecting plugins
- **Touchpoints**: #6 (client style injection)
- **Action level**: informational
- **Symptoms**: previously, disabling or enabling one plugin could remove styles owned by other plugins until a page refresh; style tags are now claimed by their injecting factory, and a failed factory's untagged styles are removed rather than lingering.
- **Migration recipe**: none required; if your plugin previously re-injected styles on activation events as a workaround, that workaround can be retired.
- **Verification**: toggle a neighboring plugin on and off; your plugin's styles survive without a refresh.
- **Source**: [aa5334f1e](https://github.com/deepseek-ai/deepseek-harness/commit/aa5334f1e) `fix(client-modules): claim only styles a factory injects`, [015349e4a](https://github.com/deepseek-ai/deepseek-harness/commit/015349e4a) `fix(client-modules): remove untagged styles of a failed factory`. Release notes: "修复启停插件时其他插件的样式被移除、需要刷新页面才能恢复的问题".

### DSH-0.2.1-A1-06 · Plugin installs report the actual version; pnpm's release-age cooldown may install an older release

- **Type**: behavior
- **Applies to**: plugins with self-update flows or version-pinned install instructions
- **Touchpoints**: none (plugin-manager surface)
- **Action level**: informational
- **Symptoms**: plugin installation results now show the version actually installed, and when pnpm's new-release cooldown policy selects an older release, the manager explains the supply-chain policy and how to request the exact version. An update flow that assumes `add <name>` yields the newest tag can therefore observe an older version than intended.
- **Migration recipe**: self-update prompts should read back and display the installed version after the install, and offer the exact-spec form (`<name>@<exact-version>` or the pinned `github:` tag) when the newest is cooled down.
- **Verification**: run an install of a freshly published version within the cooldown window and confirm your flow reports what actually landed.
- **Source**: [bab69fbec](https://github.com/deepseek-ai/deepseek-harness/commit/bab69fbec) `feat(plugin-manager): name the exact spec when pnpm installs an older version`, [0bd149294](https://github.com/deepseek-ai/deepseek-harness/commit/0bd149294) `fix(ui-plugin-manager): state the supply-chain policy, risk and remedy in the version notice`, [43c5f1e92](https://github.com/deepseek-ai/deepseek-harness/commit/43c5f1e92) `fix(plugin-manager): explain another installed version only for one-registry runs`. Release notes: "插件安装结果显示实际安装版本；因新版本冷却策略安装较旧版本时，提供说明和精确版本安装方式".

### DSH-0.2.1-A1-07 · Runtime dependency-mapping lifecycle: enabling a bundle resolves its dependencies; disabling or uninstalling clears stale mappings

- **Type**: fix
- **Applies to**: bundle authors and plugins installed as bundle dependencies
- **Touchpoints**: none (packaging/dependency special surface)
- **Action level**: informational
- **Symptoms**: enabling a newly installed bundle no longer fails to find its dependencies, and disabling or uninstalling no longer leaves stale dependency mappings behind. Replacing an installed package's **version** still requires a host restart.
- **Migration recipe**: none required; install runbooks that scheduled a restart after every bundle toggle can narrow it to version replacements.
- **Verification**: enable, disable, and re-enable a bundle; `--dump-config` keeps a consistent dependency view without a restart.
- **Source**: [abf8b760e](https://github.com/deepseek-ai/deepseek-harness/commit/abf8b760e) `fix(plugin-manager): preserve live runtime resolution mappings`. Release notes: "修复新组合包启用后找不到依赖，以及停用或卸载后残留依赖映射的问题；替换已安装包的版本仍需重启".

### DSH-0.2.1-A1-08 · HMR with dev-directory watching refreshes package manifests and preserves running entry identities

- **Type**: fix
- **Applies to**: plugin development against a watched source directory (junction/link dev installs)
- **Touchpoints**: none (development-workflow surface)
- **Action level**: informational
- **Symptoms**: with development-directory watching enabled, HMR now refreshes package-entry and dependency-mapping configuration on manifest changes and correctly reloads the still-running original entry instead of evicting it; CommonJS request refresh no longer evicts modules.
- **Migration recipe**: none required; dev-loop restart rituals after editing `package.json` (or adding exports) can be lighter.
- **Verification**: edit a watched plugin's manifest and confirm the running entry reloads rather than disappearing until a manual restart.
- **Source**: [6fe4a2e18](https://github.com/deepseek-ai/deepseek-harness/commit/6fe4a2e18) `fix(hmr): invalidate changed package manifests`, [b1c5f861b](https://github.com/deepseek-ai/deepseek-harness/commit/b1c5f861b) `fix(hmr): preserve loaded entry identities across manifest changes`, [d7d2e5fd4](https://github.com/deepseek-ai/deepseek-harness/commit/d7d2e5fd4) `fix(hmr): refresh CommonJS requests without evicting modules`. Release notes: "启用开发目录监听后，HMR 可刷新包入口和依赖映射配置，并正确重载仍在运行的原入口".
