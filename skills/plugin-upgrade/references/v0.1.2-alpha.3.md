## Corridor finding: no plugin-facing changes

- **Scale**: 117 commits between the two tags, mostly web client (turn rail, session
  projection) and session work.
- **Per-package verification** — every runtime API surface third-party plugins touch,
  compared at the two tags:
  - `@deepseek-ai/dsh-tools` (defineTool / register / ToolDefinition),
    `credentials`, `llm`, `agent`, `settings`, `host/webserver` (`WebRoute`),
    `vendor/cordis`: only `package.json` version bumps, no source changes.
  - `@deepseek-ai/dsh-client-connection`: the host RPC face plugins use
    (`rpc.ts` handle / intercept) is unchanged; its client-side transport
    (`src/client/connection.ts`) has one non-plugin-face change — a stalled
    transport-ready wait now logs a warning instead of aborting the connection
    generation.
  - `bundle/web-app` patch layer adds one built-in row, `session-turn-outline`
    (`@deepseek-ai/dsh-session-turn-outline`), for the whole-log turn rail. The row is
    bundle-internal; third-party plugin loading is unaffected.
- **npm channels**: the `alpha` dist-tag now resolves to `0.1.2-alpha.3`;
  `latest`/`next` still resolve to `0.1.1-rc.2`.
- **Batch re-validation**: the 17 omdsh-dev plugin repositories passed
  typecheck/tests/build and a real-harness tool smoke against a source checkout of
  `dsh-v0.1.2-alpha.3` with **zero code changes**. The only defect found (a
  `session_health` stats input check) is plugin-internal and unrelated to this edge.
- **Conclusion**: treat this edge as a no-op corridor. The dual-compat baseline is
  unchanged — devDependencies stay on the npm release line (`0.1.1-rc.2`), runtime
  verification against the `alpha` line.
