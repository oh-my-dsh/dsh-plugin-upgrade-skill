### DSH-0.2.2-A2-01 · Plugin Manager grows third-party package updates: rich-text detail pages, update installs with old-version recovery on failed hot-apply

- **Type**: capability
- **Applies to**: every published plugin — the manager can now update third-party packages and render their README as a rich detail page; plugins distributed via npm/git channels gain an in-app update path previously reserved for first-party bundles
- **Touchpoints**: #5 (plugin detail page renders plugin-owned README content); install/update surface otherwise
- **Action level**: optional
- **Symptoms**:
  - The plugin-manager package adds ~20 files: `typert.remote-client`, `types/build-approval`, `types/bundle-detail`, `types/git-transport`, `types/versions` — the update pipeline validates versions, approves builds, and can fetch via a git transport.
  - Updating a third-party plugin package that fails to hot-apply falls back to the old version instead of leaving the profile broken.
  - The detail page renders plugin README (rich text); a plugin with sparse or unlocalized README content will look sparse there too.
- **Migration recipe**:
  1. Nothing mandatory. Optional polish: keep the plugin README presentable (headings, badges, screenshots) — it is now first-class UI content.
  2. If a plugin ships its own update-check chip (as file-trace does), the native manager update path is additive, not a conflict — the chip reads tags, the manager installs.
- **Verification**: open the plugin manager on the new host, confirm the fleet's entries render with detail pages; run one no-op update to see the approval/rollback path resolve.
- **Source**: [dsh-v0.2.2-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-alpha.2)（"插件管理页支持展示富文本详情"、"插件管理支持更新第三方插件包；热更新失败时会尝试恢复旧版本"）; first-hand npm pack diff of `@deepseek-ai/dsh-plugin-manager` rc.4 → alpha.2 (17 changed, 20 added files).
- **Field note** (first-hand, 2026-10-28): the six maintained plugins install via profile link/manual channels and are outside the manager's bundle management (consistent with the 0.1.6-alpha.2-era finding); the new update path is relevant the day the fleet moves to registry distribution.

### DSH-0.2.2-A2-02 · Web Client mobile & narrow-screen overhaul plus composer quoting: a new GUI asset bundle

- **Type**: capability
- **Applies to**: plugins contributing UI (slots) — the whole shell is restyled for touch/narrow screens and the composer gains quoting; this card covers the visual/interaction changes only — client API changes on the same edge (for example `file-drag-callbacks`, `model-badge-package-removal`) are listed in the coverage gap below
- **Touchpoints**: #5 (Web Client seat — composer/settings/sidebar visuals)
- **Action level**: informational
- **Symptoms**:
  - `dsh-web-frontend` ships an entirely new asset bundle (new index js/css hashes, new touch icon, language-chunk reshuffles) — every shipped GUI surface was rebuilt.
  - Mobile/narrow behavior: fewer auto keyboard popups, keyboard dismiss after send, fullscreen settings with lateral navigation on narrow screens, 16px touch inputs, hover-hints no longer block touch actions.
  - Composer: chat text can be quoted into the input with a compact preview after send; drafts (with quotes and attachments) survive failed sends; the input is read-only while a send is in flight.
  - Session list/plugin icons, step-collapse retaining assistant text, Markdown copy of a full session, six new UI locales.
- **Migration recipe**:
  1. None for the visual changes. Plugins rendering their own panels should spot-check narrow-width layout once (the host itself now exercises narrow screens far more).
- **Verification**: run a session on a narrow window; confirm any contributed header/sidebar entry stays reachable and legible.
- **Source**: [dsh-v0.2.2-alpha.2 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.2.2-alpha.2)（移动端/窄屏与引用插入等条目）; first-hand npm pack diff of `dsh-web-frontend` (index/assets replaced wholesale).
- **Field note** (first-hand, 2026-10-28): the games panel (minigames) and the trace drawer (file-trace) both already handle narrow widths from their own 0.2.x-era fixes; nothing regressed in the contract sweep below.

### DSH-0.2.2-A2-03 · Six-plugin contract sweep on the new host: every slot, optional service, and remote API the fleet uses is alive

- **Type**: fix
- **Applies to**: the maintained fleet (paste-input, file-trace, input-history, ui-progress, ui-whale, minigames) and any plugin touching the same surfaces
- **Touchpoints**: none (fleet verification record — scoped to the surfaces listed below, not to the whole edge)
- **Action level**: informational
- **Symptoms**:
  - Static contract sweep against the installed `0.2.2-alpha.2` runtime: all fleet slot names (`conversation.session.header.utilities`, `conversation.session.header.actions`, `conversation.input.left`, `conversation.input.dock`, `settings.section`) present in the client-runner catalog; optional services (`uiSession`, `inputTriggers`, `jobs`) present in their provider packages; `canOpenWorkspacePath`/`openWorkspacePath`/`workspacePathApplications` present in `dsh-api-session-controller` alpha.2.
  - The sweep first scanned the wrong corpus (the frontend asset shell) and every marker read GONE — the slot catalog lives in the host-side `dsh-cordis-client-runner`, not the frontend bundle; correcting the corpus flipped everything to OK. Record kept so the next sweep does not repeat the detour.
- **Migration recipe**:
  1. For a plugin whose surfaces match the fleet's and that is unaffected by the coverage-gap guides below: add `0.2.2-alpha.2` to `compatibility.json` and cut a declaration release. Check the Node.js 24.9 floor in CI and install docs first.
- **Verification**: run the fleet's smoke surface (panel open, one game round-trip, one trace open with reveal/open gestures) on the new host.
- **Source**: primary — the published packages themselves: [`@deepseek-ai/dsh@0.2.2-alpha.2`](https://www.npmjs.com/package/@deepseek-ai/dsh/v/0.2.2-alpha.2) and its installed runtime tree (first-hand scan, 2026-10-28).
- **Field note** (first-hand, 2026-10-28): the fleet shipped same-day declaration releases on this evidence (paste-input 0.2.17, file-trace 0.4.1, input-history 0.1.30, ui-progress 0.11.12, ui-whale 0.3.34, minigames 0.8.2); paste-input's bundle version literal needed a re-stamp because the rc.4-era stamp had been lost to a later revert — worth watching on the next declaration round.
