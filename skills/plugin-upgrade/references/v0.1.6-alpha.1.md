### DSH-0.1.6-A1-01 · DeepSeek adapter defaults to the Messages protocol; custom base URLs must be reviewed

- **Type**: breaking
- **Touchpoints**: none (host config surface; DeepSeek adapter protocol default)
- **Applies to**: Deployments and plugins using DeepSeek models through a custom API base URL
- **Action level**: required-if-hit
- **Symptoms**: The DeepSeek adapter now defaults to the Messages protocol and reuses uploaded images via the Files API. Deployments that manually configured the old official root address keep their override and may fail against the new protocol expectations.
- **Migration recipe**: If a manual old official root address is configured, remove it or change it to `https://api.deepseek.com/anthropic`. Custom (non-official) API addresses are intentionally preserved unchanged — verify them against the Messages protocol before upgrading.
- **Verification**: With the upgraded host, a DeepSeek model request completes and the effective base URL in logs/config matches the intended endpoint.
- **Source**: [v0.1.6-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.1)

### DSH-0.1.6-A1-02 · PTC package/service names unified to `ptc-runtime`; old names incompatible

- **Type**: breaking
- **Touchpoints**: none (PTC package/service naming surface)
- **Applies to**: Custom plugins and configs referencing PTC package or service names
- **Action level**: required-if-hit
- **Symptoms**: PTC package and service names are unified to the `ptc-runtime` series; old names no longer resolve.
- **Migration recipe**: Update custom cordis.yml/plugin references from the old PTC names to `ptc-runtime`. The workflow executor is renamed to `workflow-ptc` and follows session-file policy; Python PTC is not supported in this release.
- **Verification**: Boot with the updated references — no unknown-package/service errors; PTC tools activate.
- **Source**: [v0.1.6-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.1)

### DSH-0.1.6-A1-04 · `agent/session-start` replaced by async serial `agent/created`

- **Type**: breaking
- **Touchpoints**: none (host agent lifecycle surface)
- **Applies to**: Plugins hooking `agent/session-start` or registering on it
- **Action level**: required-if-hit
- **Symptoms**: `agent/session-start` is replaced by `agent/created` (async serial); the first model request now waits for initialization to complete.
- **Migration recipe**: Move registrations/adaptations from `agent/session-start` to `agent/created`. Slow init in the hook now delays the first model request instead of racing it — keep the handler light or defer heavy work.
- **Verification**: With a plugin registered on `agent/created`, a fresh session reaches the first model request after the hook completes; no session-start deprecation warnings.
- **Source**: [v0.1.6-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.1)

### DSH-0.1.6-A1-05 · Session synchronous history reads deprecated (`snapshotEvents` / `eventAt` / `ownEvents`)

- **Type**: behavior
- **Touchpoints**: none (session history read surface)
- **Applies to**: Plugins reading session history synchronously
- **Action level**: optional
- **Symptoms**: The synchronous history read interfaces `snapshotEvents`, `eventAt` and `ownEvents` are deprecated. They were themselves the alpha.4-era replacements for the removed eager `Session.events` array (see [DSH-0.1.2-A1-02](v0.1.2-alpha.1.md) and its alpha.2 restore [DSH-0.1.2-A2-01](v0.1.2-alpha.2.md)) — history access keeps migrating toward on-demand/async reads.
- **Migration recipe**: Migrate history reads to the current on-demand interfaces; audit plugins that cache full event arrays. Expect the deprecated surfaces to be removed in a later release.
- **Verification**: No plugin code references the deprecated read interfaces; session history flows (replay/export) still work.
- **Source**: [v0.1.6-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.1)

### DSH-0.1.6-A1-06 · Experimental Team mode closes `subagent` / `subagent_fork` in favor of `spawn_teammate`

- **Type**: breaking
- **Touchpoints**: none (subagent tool surface; experimental Team mode only)
- **Applies to**: Workflows and automation that rely on the `subagent` / `subagent_fork` tools under experimental Team mode
- **Action level**: required-if-hit
- **Symptoms**: With experimental Team mode, subagent creation is unified to `spawn_teammate` (teammate cap raised 8 → 16) and `subagent` / `subagent_fork` are closed.
- **Migration recipe**: Port automation to `spawn_teammate`, or keep Team mode disabled. Automated pipelines that drive subagents by tool name must be updated before enabling Team mode.
- **Verification**: With Team mode on, `spawn_teammate` creates teammates and the legacy tools are unavailable; with it off, existing behavior is unchanged.
- **Source**: [v0.1.6-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.1)

### DSH-0.1.6-A1-07 · Optional plugin startup failure no longer cascades; web recovery re-registers module routes

- **Type**: fix
- **Touchpoints**: none (host/web plugin-load resilience surface)
- **Applies to**: All Web Client plugin fleets
- **Action level**: informational
- **Symptoms**: Previously an optional plugin failing at startup could take down other plugins' activation; now an optional plugin's failure does not affect other available plugins, while a required plugin failure still exits. Additionally, after Web service recovery, module route registration is fixed (stale-route symptoms after recovery are gone).
- **Migration recipe**: No action. Note the changed failure semantics for triage: a missing optional plugin no longer explains other plugins being down.
- **Verification**: Boot with a deliberately broken optional plugin — remaining plugins still load.
- **Source**: [v0.1.6-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.1)

### DSH-0.1.6-A1-08 · Node PTC runs in a separate process with empty `process.env` and per-call timeouts

- **Type**: breaking
- **Touchpoints**: none (Node PTC execution surface)
- **Applies to**: Node PTC `run_code` scripts that read `process.env`, long-running calls, or expect in-process state
- **Action level**: required-if-hit
- **Symptoms**: Node PTC now executes in a separate process, follows session-file policy, and limits output and heap; `process.env` is empty inside the script. `run_code` supports per-call timeouts (default 120 s, max 600 s).
- **Migration recipe**: Stop relying on ambient env vars inside PTC scripts — pass needed values explicitly; keep calls under the timeout budget or set a per-call timeout; do not depend on state carried across calls.
- **Verification**: A PTC script that previously read ambient env now receives values via explicit arguments and completes within the timeout.
- **Source**: [v0.1.6-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.1)

### DSH-0.1.6-A1-09 · Config hot-reload no longer rolls back on activation failure

- **Type**: breaking
- **Touchpoints**: none (host config hot-reload surface)
- **Applies to**: Operators editing cordis.yml / patch layers on a live host
- **Action level**: informational
- **Symptoms**: Config hot-reload no longer rolls back transactions: on parse failure the original config is kept, but a plugin activation failure can take effect partially — the host keeps running with a half-applied config until it is corrected and reloaded.
- **Migration recipe**: After any hot-reload error, fix the config and reload again; do not assume the previous config state was restored. Validate config edits with `dsh --version` / boot checks when plugin activation is involved.
- **Verification**: Introduce a bad activation in a test profile, reload, correct it, reload again — final state matches the intended config.
- **Source**: [v0.1.6-alpha.1 release notes](https://github.com/deepseek-ai/deepseek-harness/releases/tag/dsh-v0.1.6-alpha.1)
