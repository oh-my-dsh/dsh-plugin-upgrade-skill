**Guard hardening** specifics:

Class of breakage presence-checks can't catch:
1. Payload-shape drift below the probed member (field removed/renamed/narrowed) — exactly this case.
2. Type/semantic change of the probed member's value (same name, different payload) — `sessions.list` kept the name but changed from `SessionListState` to `SessionListSnapshot`.
3. Optionality drift: a previously always-present value now returns `undefined` for a subset of states (e.g. `current` undefined while sessions exist).
4. Signature drift: arity/required-arg changes that turn into runtime TypeErrors at call time (not caught by `typeof x === 'function'`).
5. Nesting/ownership drift: the value moved to another service (e.g. `ctx` now comes from `uiSession`).

Why the guard passed: it probes only *existence of members on ctx* (depth 1). The break is at depth 3 (`ctx.sessions.list` → `getSnapshot()` → `.current`).

Hardened guard — probe the **value the plugin actually consumes**, at the granularity it consumes it:
- Structural (activation-time, safe): `typeof ctx.sessions?.list?.getSnapshot === 'function'`, `typeof ctx.sessions?.scope === 'function'`, `typeof ctx.uiConversation?.binding === 'function'`.
- Shape (must run when a session is bound): the snapshot must carry the plugin's required fields — for the legacy path `'current' in snap`; for the new path `uiSession.adapter.current.getSnapshot()` must yield `{key, ctx}` with `ctx.get` a function.
- End-to-end value probe (the real fix): from a bound session, the plugin must be able to obtain: an id (string), a session ctx with `.get`, a `conversation` service with `.input.for(ctx)` and `.state.getSnapshot().draft` (string), `setDraft` (function), and chat nodes (array). Assert all of these — this is a *capability* probe, not a *presence* probe.
- Cross-check invariant that detects field-removal specifically: **"the host has sessions but the plugin cannot resolve the current one"** → incompatible host, not "not ready". On alpha.2: `sessions.list.getSnapshot().items.length > 0` (catalog non-empty) while `current`/binding id is unavailable → LOUD. On alpha.1: `byId` non-empty and `current` defined → fine. This turns "silently no session" into "silently incompatible".

Lifecycle timing:
- Structural probes: at activation (as today).
- Shape/capability probes: at the **first moment a session is actually bound** — i.e., react to `uiSession.adapter.current` (new path) / the session-list snapshot (legacy path) becoming non-absent, not at plugin activation (at activation there is no session, so the value probe would false-negative). Also re-probe on session change.
- Additionally: **fail loudly rather than bail** — replace `return null` with a discriminated result: `no-session` (legit, silent) vs `incompatible` (loud: console.error + remediation banner + a thrown error surfaced to the host's plugin error channel). Currently `null` conflates "no session yet" with "API gone".
- Also probe **at the point of use** (first keystroke) so a break that appears mid-session (e.g. host hot-swap) is caught, and cache the verdict so it doesn't spam.

Now §4 guard hardening in detail.

Class of breakage presence-checks cannot catch:
- **Field-level removal/rename inside a returned value** — the guard sees `ctx.sessions.list` (a live object) but not the *members of its snapshot value*. This is the exact failure.
- **Type/shape changes of return values** (e.g. `current` → `key`; `byId` map → `items` array; `SessionListState` → `SessionListSnapshot`).
- **Semantic changes** (same member names, different meaning — e.g. `binding.key` becoming an "address" instead of an id, or `ctx` being the root ctx instead of the session ctx).
- **Contract drift on nested values** (`chat.legacy.nodes`).
- **Contract drift on method results** (`scope(id)` returning a different thing).
General: **presence checks verify the service *surface*, but the plugin's real dependency is on the *data contract* behind the surface.** They also can't distinguish "member exists but is a different kind of thing" (e.g. `list` changed from a snapshot to a plain object).

Hardened guard: probe **capabilities end-to-end with data**, i.e. run the plugin's own resolution once and validate the *shapes* of the values it will consume. Concretely:

```ts
interface ProbeResult { ok: boolean; missing: string[] }

function probeHostCapabilities(ctx: ClientContext): ProbeResult {
  const missing: string[] = []

  // (A) session identity + session-scoped ctx, from whichever channel the host provides
  const uiSession = (ctx as MaybeUiSession).uiSession
  if (uiSession !== undefined) {
    const adapter = uiSession.adapter
    if (adapter === undefined || adapter.current === undefined) { missing.push('uiSession.adapter.current'); }
    else {
      const snapshot = adapter.current.getSnapshot()
      // shape check, value-tolerant: the host may legitimately publish an absent binding
      if (snapshot === undefined || snapshot === null) missing.push('uiSession.adapter.current snapshot')
      else {
        if (!('key' in snapshot)) missing.push('SessionBindingValue.key')
        if (!('ctx' in snapshot)) missing.push('SessionBindingValue.ctx')
      }
    }
  } else {
    const sessions = ctx.sessions
    const snapshot = sessions?.list?.getSnapshot?.() as Record<string, unknown> | undefined
    if (snapshot === undefined) missing.push('sessions.list snapshot')
    else if (!('current' in snapshot)) missing.push('SessionListState.current (legacy) — the host removed the legacy current-session field')
  }

  // (B) the session-scoped conversation service must be reachable *through* the scoped ctx
  // ... probe only when a session is actually bound (see lifecycle note)

  // (C) the chat view must still expose nodes
  ...
  return { ok: missing.length === 0, missing }
}
```

Key: `'current' in snapshot` — property-presence, not value-presence. This distinguishes "host removed the field" from "no session currently bound" (alpha.1 with `current === undefined` still has `'current' in snapshot === true`). And it works at activation even when no session is bound.

And crucially: the probe must ALSO include the **data-shape probe of the values** (not just presence), and it must be run:
1. **at activation** for structural facts (property presence, service shape) — safe because it tolerates "no live session";
