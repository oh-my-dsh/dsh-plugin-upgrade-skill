# S23 The passing compat guard (calibration answer)

## 1. Silent-failure attribution

The broken read is in the plugin's resolve(): sessions.list.getSnapshot() succeeds
(the list observable still exists on alpha.2) but the published snapshot shape changed —
alpha.1's SessionListState carried a current field; alpha.2's SessionListSnapshot has
items/state/phase/error/subagentsByParent/jobsBySession and NO current. So .current is
undefined on every keystroke, resolve() returns null, and onKeyDown exits before
preventDefault — the chord falls through untouched.

Both silences have distinct causes. The compat guard passes because its four checks
(sessions.list, sessions.scope, sessions.sessionOf, uiConversation.binding) are
service-member presence probes: the service, its members, and even the observable all
survive the refactor — only a field inside the published value is gone, which presence
checks cannot see. And there is no console error because nothing throws: reading a
missing property yields undefined, which the plugin treats as the legitimate "no session
open" state it was designed to ignore quietly.

## 2. Evidence mapping

Comparing the two type excerpts: SessionListState.current (alpha.1) is gone; the
alpha.2 ISessions.list doc comment says navigation belongs to view owners. The
replacement is the new uiSession service from @deepseek-ai/dsh-client-ui-session: its
adapter.current is an ObservableSnapshot<SessionBindingValue> whose value is
{ key, ctx, hooks, keyedHooks, props } — key is the bound session id (the current
replacement) and ctx is the session-scoped context (the sessions.scope(id)
replacement). The absent binding publishes an absent value with key undefined,
preserving the no-session semantics.

## 3. Migration recipe

export const inject = ['sessions', 'uiSession', 'uiConversation', 'conversation']

const currentSession = (): { sessionId: string; scope: ClientContext } | null => {
  if (ctx.uiSession !== undefined) {
    const snap = ctx.uiSession.adapter.current.getSnapshot()
    if (snap !== undefined && snap.key !== undefined && snap.ctx !== undefined) {
      return { sessionId: snap.key, scope: snap.ctx }
    }
    return null
  }
  const id = sessions.list.getSnapshot().current
  if (id === undefined) return null
  const scope = sessions.scope(id)
  return scope === undefined ? null : { sessionId: id, scope }
}

resolve() then reads scope.get('conversation') through the binding value's ctx and
passes that scope to conversation.input.for(scope). inject gains uiSession so the
fiber waits for the service where it exists; the legacy branch keeps one build serving
both hosts.

## 4. Guard hardening

The shipped guard cannot catch field-level removal behind service-level stability,
checked once at activation while the break recurs per keystroke. A hardened guard probes
the actual capability: assert the specific snapshot field on alpha-1-shaped hosts
(typeof list.getSnapshot().current) and/or feature-detect uiSession on alpha-2-shaped
hosts — and run the probe lazily or per-use, not only at activation.

## 5. Verification and prevention

Verify without a full migration: probe adapter.current's key with one session open;
after the code change the chord recalls history on both hosts; typecheck against
alpha.2's published types is the strongest pre-ship gate. Host-side prevention: a
removed public snapshot field should fail loud — a deprecated getter that throws or
warns on read, or a runtime snapshot-shape contract guards can pin.
