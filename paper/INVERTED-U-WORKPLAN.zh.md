# 倒 U：工作建议与投稿前清单

更新：2026-09-15。**这是论文当前唯一的执行清单。** 旧审稿、修改记录和审计账本保留证据，不另行定义优先级。本文件是回顾性分析与补充实验建议，不是预注册、已完成结果或开跑授权。

## 1. 目标和投入边界

用户选择：保留倒 U，不大规模补实验。当前默认先用已有数据检查形状和评分，不新增 solver 调用。

当前可写：五组历史配置的 skill **绝对增益**呈中间较高、两端较低的描述性模式，与倒 U 假设一致。任务、评分、skill 版本、harness 和部署不同，不能将横轴当独立模型能力，也不能归因为能力导致的规律。

| 主张层级 | 需要什么证据 | 当前状态 |
|---|---|---|
| 描述性倒 U | 原始点、区间、协议差异、天花板及超时边界 | 已进入主稿；稳定性与评分复核待补 |
| 所测配置支持中档增益最大 | 统一协议的三档双臂实验，直接比较中档与两端增益 | 未完成 |
| 普遍能力规律或机制 | 独立能力依据、更多能力点/家族复现及针对性控制 | 当前不追求 |

不能通过挑任务、挑轮次、只追加有利组或选择检验方法来维持倒 U。结果不稳定时降低主张，而不是设法让图更像倒 U。

## 2. 第一步：已有数据重分析（0 次新 solver 调用）

### A1. 直接比较增益差

- [ ] 优先比较两组 GLM，共同任务均为 S1–S22。
- [ ] 每题计算 `d_t = (中档 skill − 中档 no-skill) − (强档 skill − 强档 no-skill)`，再汇总和给出区间。
- [ ] 已有点估计相差约 6.22 分；**尚未计算并确认这个差值的区间**。
- [ ] 保留预算、材料与评分的差异说明。共同任务不会自动使旧实验成为受控比较。

### A2. 稳定性与天花板

- [ ] 各轮分别计算效应；在有原始重复分数的组比较均值/中位数口径。
- [ ] 逐题移除分析，报告范围与贡献集中的任务，不能只展示保留峰值的版本。
- [ ] 有共同任务且分数可解释时做共同子集分析，不能把不同评分尺直接视为同一尺度。
- [ ] 同时展示基线和绝对增益；报告剩余提升空间相关敏感性分析。
- [ ] 记录任务可能共享事件的相关性；有可辩护的事件分组时做分组重采样，否则披露任务 bootstrap 的限制。
- [ ] 缺失分数、超时与基础设施错误单列；timeout 不等于功能失败。

**统计边界：**均值 bootstrap 与 Wilcoxon signed-rank 检验不是两个独立确认。一个组显著、另一个不显著，不等于两组效应存在显著差异。所有新分析应标为回顾性探索，报告分析选择和完整结果。

**交付：**可复算脚本、输入哈希、结果 JSON、论文中的一张稳健性表，以及对形状是否稳定的直接结论。

## 3. 第二步：已有答案评分复核（用户协助安排）

优先复核支撑中间峰值的 GLM-5.3-flash，而不是再增加模型。

- [ ] 邀请熟悉迁移契约、尽量未参与原评分的人；如实记录身份/角色、参与过什么。
- [ ] 开始复核前固定抽样与轮次选择：可先抽 12–16 题、每题两臂各一份答案，共约 24–32 份；覆盖提升、退步和零差异。
- [ ] 隐藏模型名、条件和原分数，以任务契约确定 rubric。答案内容仍可能暴露条件，不能保证完全盲。
- [ ] 若按历史增益分层抽样，说明抽样方式，不能将抽查样本均值直接当总体增益。
- [ ] 保存逐项理由，检查正确改写、无引用正确答案、关键词堆砌错误答案和相互矛盾建议。
- [ ] 如发现系统性评分偏差，再扩大复核；重评另存版本，两臂采用相同标准，不覆盖历史成绩。

**交付：**匿名答案包、固定抽样规则、rubric、真实复核记录、分歧与修订说明。小样本抽查不是整个 benchmark 的效度认证；第二个 LLM judge 只能作敏感性分析。

## 4. 决策点：先检查，再决定是否花预算

完成第 2–3 节后，给出以下之一：

1. **形状稳定且评分复核支持关键收益**：保留探索性倒 U，并考虑是否做统一三档补充验证。
2. **右端下降主要由天花板解释**：保留“绝对收益在中档较大”的部署观察，不写强模型不会利用 skill。
3. **形状依赖少数题/轮次/评分方式**：降低倒 U 地位，转为 benchmark 与异质性分析。

如果决定不新增模型实验，完成这些检查后即收束论文，不把四条件、跨生态和所有机制实验变成默认任务。

## 5. 可选核心实验：三个代表配置的统一对照

仅当希望将描述性观察升级为“所测配置支持中档收益最大”时执行。三档最多支持所测配置中的峰值，不足以确认连续函数形状或普遍能力规律。

### 推荐模型与任务：优先 192 次

沿用已有实验的三个代表模型，先不增加 Terra、DeepSeek 或 Astra 的 solver 实验。选择这三者是为了在统一协议下复核历史模式，属于回顾性发现后的定向验证，不是独立选出的能力标尺。

| 模型 | 历史位置及新实验目的 | 新跑条件 | 16 题方案 |
|---|---|---|---:|
| Qwen3.8-27B | 历史低基线组；检查统一题池、减少超时干扰后，增益是否仍低于 GLM-5.3-Flash | no-skill / with-skill | 16×2×2＝64 trials |
| GLM-5.3-Flash | 历史中间组；检查统一评分后较高增益是否保留 | no-skill / with-skill | 64 trials |
| GLM-5.2 | 历史高基线组；检查相同条件下绝对增益是否仍较小 | no-skill / with-skill | 64 trials |
| **合计** | 三个配置、每格两次 | 两臂 | **192 trials** |

模型官方入口：[Qwen3.8-27B](https://huggingface.co/Qwen/Qwen3.8-27B)、[GLM-5.3-Flash](https://huggingface.co/zai-org/GLM-5.3-Flash)、[GLM-5.2](https://huggingface.co/zai-org/GLM-5.2)。运行前核实端点是否提供对应模型，记录实际服务端模型标识、供应商、权重 revision（可获得时）、量化方式和时间；不能仅凭自定义模型别名认证身份。

**“弱、中、强”仅指历史成绩位置。** 如果没有独立能力依据，新实验报告三个具名配置的增益差，不把它们重新包装为已认证的能力梯度。若新结果不再呈现原顺序，完整报告，不事后调换标签维持倒 U。

**优先限定静态迁移诊断。** 从 S1–S22 中按来源事件、问题类型和材料长度分层，在看新成绩之前用固定种子抽取 16 题，记录纳入理由。预算更紧则事先定为 12 题，共 144 trials；不要根据前 12 题是否显著决定补到 16 题。难度覆盖依据应独立于 skill 增益，不能专挑有利题。固定 task/fixture/rubric 版本，并保证每个条件都明确允许读取自己获配的材料。

该任务集属于已有开发暴露的静态任务子集，结论限于诊断任务；不能据此声称实际代码修复或未见事件的泛化规律。

### 设计与执行一致性

| 维度 | 要求 |
|---|---|
| 三个配置 | 默认用上述具名模型；只有取得独立依据时才称能力梯度，不能按此次 no-skill 分数事后定义能力 |
| 能力依据 | 优先事先选择的相关独立评测/开发任务；同家族有助于减少差异，但参数量本身不保证能力顺序 |
| 任务 | 相同题池，按来源、类型及独立于 skill 增益的难度覆盖选取；不能为保留倒 U 选题 |
| 两臂 | no-skill / with-skill；固定完整 skill 字节与挂载方式 |
| 执行 | 同一 harness、提示规则、工具/网络权限和预算政策；条件交错或随机执行 |
| 重复 | 各组相同重复次数；完整保存所有尝试与对称重试规则 |
| 评分 | 同一 rubric 和 grader；静态、行为验收及引用合规分开 |
| 基础设施 | 预演检查服务吞吐、限流和环境准备；若混用部署，则能力与部署仍不可完全分离 |
| 产物 | 答案/补丁、评分细项、模型与工具版本、输入/输出 token、耗时、终止状态和哈希 |

### 预演与 Qwen 超时处理

旧 Qwen 报告记录本地单张 H20 部署，许多 S 系任务为 300 秒限制，超时明显。此次先用不进入正式统计的独立开发题检查运行链路和费用；正式运行前锁定输出/工具调用预算、上下文限制以及足够宽松的墙钟安全上限，具体数值由预演确定，不照搬旧 300 秒。若采用复用旧开发题的预演，也必须明确其开发用途。

- 三个配置采用相同预算政策，并记录实际输入/输出、生成量、服务延迟、工具调用、终止原因及预算截止产物。
- 不能认为各模型的 `medium` / `high` 表示相同推理预算；分别记录模型支持的设置及实际执行行为。
- Qwen 本地、GLM API 的组合仍混入部署差异；减少超时后也不能宣称完全隔离能力因素。同一 token 数在不同 tokenizer 下也不代表相同计算量。
- 正式两臂全部新跑；本方案不把旧 GLM 或 Qwen 分数拼入新主表。旧历史表单独保留。

### 新实验的评分安排

静态诊断优先以隐藏模型和条件的人工 rubric 评分为主要依据。192 次运行最多对应 192 份待评答案；需预先核算人工时间，人工复核旧结果的 24–32 份抽查不替代新实验评分。

如只能人工抽查，所有新输出仍须用同一固定评分器与 rubric，按统一规则覆盖三个模型及两臂，报告抽查范围和评分不确定性。不要继续让 GLM 给自己的关键结果单独定分；其他家族的 LLM judge 可辅助，但不能自动当正确性标准。记录每项依据，诊断正确性与引用/格式合规分开。

### 有限预算示例

- 12 题 × 3 档 × 2 条件 × 2 次 = **144 个 solver trial**。
- 16 题 × 3 档 × 2 条件 × 2 次 = **192 个 solver trial**。

只是候选规模，**不保证统计功效**。先用已有方差估计可检测效应或预期区间宽度，固定预算、停止和缺失处理规则。重复次数不能替代独立任务数量；另计校准、judge 和失败重试费用。

不要直接将新 no-skill/doc-only 臂和不同配置/版本的旧 skill 臂拼接；旧运行只有证据证明完整协议一致时才可复用。

### 主要分析

先按任务汇总各臂两次重复，再按任务等权计算每个配置的 `Δ = 平均(with-skill − no-skill)`。预先指定：

- `ΔGLM-5.3-Flash − ΔQwen3.8-27B`；
- `ΔGLM-5.3-Flash − ΔGLM-5.2`。

它们对应历史模式中的中间组对两端的增益差，不意味着已独立认证模型能力顺序。

保持任务配对；有已审定事件分组时考虑相关性。报告两个直接差异的区间和多重比较处理，不以每档是否显著代替交互比较。使用均值作为目标时，所选检验/区间要与该目标一致。

若两侧差异均有支持，可写“在所测三个配置、静态任务与预算下，GLM-5.3-Flash 绝对增益最大，与历史倒 U 假设一致”。若证据不清楚，报告不确定，不能靠三点拟合二次曲线宣称规律。

## 6. 可选机制实验：有明确问题才补

第一轮只做 no-skill / with-skill，不默认加入 docs-only 或第四、第五个模型。以下扩展单列为后续实验，不因看到第一轮结果而改写其任务、主要比较或预算规则。

- **Qwen 仍频繁超时**：同一 Qwen 配置两臂同时增加预算，检查增益是否恢复。
- **GLM-5.2 仍接近满分**：另设事先选定的较难补充集，三个模型都跑；主实验照常报告。
- **要解释中间组收益来源**：优先为 GLM-5.3-Flash 新跑匹配的 docs-only / skill+同源 docs 对照，不直接沿用不匹配的旧 skill 臂。


| 未排除的问题 | 最小针对性对照 | 解释边界 |
|---|---|---|
| 左端由超时造成 | 同一弱模型，两臂同时提高预算；其他条件固定 | 恢复增益支持资源约束解释；未恢复不等于证明能力机制 |
| 右端只是天花板 | 预先选择较难任务，三个配置都跑 | 强档在有提升空间时是否仍少获益；不能只按旧结果为强档挑题 |
| 流程组织还是事实供给 | docs-only vs skill+相同 docs | 不必为了形状一开始就做；12 题×2 臂×2 次=48 trial 仅为规模示例 |
| 长度干扰还是内容误导 | 等长无关材料或相应内容消融 | 同源资料相同不等于长度已控制 |

当前不默认执行这些机制实验、完整 A/B/C/D 设计、跨生态或大规模模型扩展。`study-v1/` 和 `benchmark/holdouts/` 是保留的独立协议/基础设施，不是当前倒 U 计划的运行器，也不是已执行结果。
