# Bounded retrospective mechanism and statistical checks

This protocol is written after the original results and case selection were known, before running the new probes. It is not a preregistration or a new solver evaluation.

Scope: S11 with-skill repeat 1's exact proposed containment function, S18 with-skill repeat 2's cleanup recommendation versus the rubric's mounted-host liveness requirement, and all 16 focal task pairs under the original and both previously reported replacement endpoints. No new scores replace original verdicts.

S11: extract the reviewed function with only TypeScript annotations removed, check seven explicit inputs under each of Node's POSIX and Windows path algorithms. Include root, descendant, parent, higher ancestor, sibling-prefix, dotted descendant, and case/drive controls. Compare against declared expected lexical containment. This is not native Windows filesystem testing, symlink resolution, HTTP exploit testing, or an end-to-end plugin repair.

S18: the archive contains a description of the timer planner, not its implementation. Reconstruct a minimal self-rearming timer and component state. Compare a mounted referenced chain, a cleanup callback that is never invoked, explicit unmount plus cancellation, unref on every new timeout, and unref only on the first timeout with another handle initially keeping the loop live. A readiness marker distinguishes startup failures from liveness failures. The parent terminates continuing children after a bounded observation window. This tests the described mechanism, not the original CI host or a full submitted patch. Explicit teardown is a positive alternative control, not an assumed failure.

Statistics: enumerate all sign assignments for nonzero paired task differences (two-sided absolute sum statistic), under each of the original, S11-only, and combined review endpoints. Report the symmetry/exchangeability assumption and that deterministic arm scheduling does not justify a randomized causal test. Also report every leave-one-task-out mean and both repeat-wise means. No endpoint or test is selected by significance.

Do not infer failure prevalence, intervention effectiveness, independent human agreement, cross-project generalization, or functional repair rates from these checks. S6 remains a static contract assessment; no mock API will be presented as verification of the actual target public API.
