## S11：直接执行原回答中的谓词

从 with-skill r1 原文提取 `contained`，只去掉 TypeScript 类型。对 Node 的 POSIX 和 Windows 路径算法各运行 7 个预先列明的输入：本目录、正常子项、父目录、更高祖先、同前缀兄弟目录、点号子目录及平台特定控制。

14 个输入中，两种算法都把父目录错误判为包含，其余 12 个控制行为符合预期。不是“漏洞率 2/14”，不是 Windows 原生文件系统验证，也没有测试完整 HTTP 路由或利用链。

## S18：区分可行替代修复与更窄的评分标准

归档里只有 planner 行为描述，没有原实现。因此使用独立 Node 子进程重建最小重排计时器，并明确不称其为完整插件测试。

| 条件 | 观察结果 |
|---|---|
| 持续 mounted、计时器保持引用 | READY 后 700 ms 仍存活，父进程结束它 |
| 定义 cleanup，但 host 从不调用 | 同上 |
| host 主动 unmount 并取消当前计时器 | 自然退出 |
| 每次新计时器都 unref | 自然退出 |
| 仅首个计时器 unref，另一个句柄暂时保持事件循环 | 后续引用计时器继续存活，到观察上限被结束 |

**修正原文解释：主动卸载并非无效修复。** 在最小重建中，只要 host 实施 teardown，就可以退出。原 rubric 要求的是 host 不卸载也不被动画计时器单独阻止退出；它比 instruction 中“one-line fix”的要求更具体。保留原先 90 分及原复核分数，但不再把这项扣分等同于“答案无法解决挂起”。

## 小样本数值复核

`paper/generated/focal-robustness.json` 保留三个既有评分端点的全部 16 个留一结果、两次重复均值，以及 8 个非零任务差的 256 个符号组合。

| 端点 | 均值差 | 双侧符号枚举尾部比例 | 留一均值范围 |
|---|---:|---:|---:|
| 原判 | 4.921875 | 20/256 = 0.078125 | 2.4167–5.5833 |
| 仅 S11 替换 | 4.609375 | 34/256 = 0.1328125 | 2.0833–5.5833 |
| 全部既有重点复核替换 | 5.390625 | 30/256 = 0.1171875 | 2.9167–6.4167 |

枚举以绝对任务差总和为统计量，包含相等极端值；依赖独立任务差的条件符号可交换性。执行顺序不是随机分组，不将其称为随机试验的因果检验。它是后验描述性敏感性，不取代原 bootstrap，也不选择最显著的端点。方向为正不等于已确证总体收益。

## 复现

在仓库根目录运行 `npm run check:paper-mechanisms`。它重新执行探针并核对保存的结果，再验证数值枚举。更新归档时分别运行 `node paper/scripts/check-case-mechanisms.mjs` 和 `node paper/scripts/analyze-focal-robustness.mjs`。原判和原回答始终不改。
